#### 6c. Schema Template Correctness Audit

**13 prioritized issues identified (P0-P13):**

| Priority | Issue | Category | Template-Expressible? |
|---|---|---|---|
| **P0** | Returned-string template syntax bug - `$Properties[...]` inside C# helper return is output literally | Critical bug | Yes - restructure output section |
| **P1** | Nullable reference recursion infinite loop - `GetInnerType` returns same type for `string?` | Critical bug | Yes - reorder checks |
| **P2** | Inherited properties missing - `$Properties` only iterates own properties | High correctness | Yes - walk `BaseClass` in C# |
| **P3** | Enum always `schema.string()` - numeric enums should be `schema.number()` | High correctness | Yes - needs `Template(Settings, File)` |
| **P4** | Required vs optional not distinguished | Medium correctness | Yes - `property.IsRequired` + `JsonRequired` |
| **P5** | Polymorphism regex bugs - single digit only, `Replace` vs `Match` | Medium correctness | Yes - fix regexes |
| **P6** | Serialized naming policy - fallback always camelCase | Medium correctness | Yes - parameterize fallback |
| **P7** | WireFormat not read from attribute | Medium feature | Yes - parse `Attribute.Arguments` |
| **P8** | TimeZoneProperty not in runtime schema | Medium feature | Template yes, runtime needs `ZonedDateTimeSchema` enhancement |
| **P9** | FrontendNoTransform in model template | Medium feature | Workaround yes, engine preferred |
| **P10** | Generic schema factories | Medium feature | Yes - complex helper logic |
| **P11** | Newtonsoft schema templates missing | Low feature | Yes - new template files |
| **P12** | JsonInclude / non-public properties | Low edge case | No - needs engine change |
| **P13** | JsonExtensionData support | Low edge case | Partially - needs `ObjectSchema` enhancement |

**Key fix for P0:** Build entire schema string in C# helper methods (no template syntax like `$Properties[...]` inside returned strings). Use template syntax only in the output section for imports and entry points.

**Key fix for P1:** Check type-specific properties first (Guid, decimal, date, enum, etc.), then wrap in nullable. Current code checks `IsNullable` first which causes infinite recursion for nullable reference types.

**Key fix for P2:** Walk `BaseClass`/`BaseRecord` chain in C# to collect all properties including inherited ones. `$Properties` template syntax cannot do this.

**Key fix for P3:** Use `Template(Settings settings, File file)` constructor to access `file.Enums` for checking enum string conversion attributes (`AsString`, `JsonStringEnumConverter`, `StringEnumConverter`).

```typescript
import { useQuery, useMutation } from '@tanstack/react-query';
import { fetchJson, serializeJsonBody } from '@adaskothebeast/typewriter-http-fetch';
import { apiTypeRegistry } from '../models/typewriter-registry';
import { SimpleModelSchema } from '../models/SimpleModel.schema';

// GET endpoints -> useQuery hooks
export function useGetSimpleModelQuery() {
  return useQuery({
    queryKey: ['simple'],
    queryFn: () => fetchJson('/api/simple', SimpleModelSchema, undefined, {
      registry: apiTypeRegistry,
    }),
  });
}

// POST/PUT/DELETE endpoints -> useMutation hooks
export function usePostSimpleModelMutation() {
  return useMutation({
    mutationFn: (data: SimpleModel) =>
      fetch('/api/simple', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: serializeJsonBody(data, SimpleModelSchema, {
          registry: apiTypeRegistry,
        }),
      }),
  });
}
```

## Architecture Summary

```
User selects date library via:
  1. Template configuration (Settings.UseDateLibrary / typewriter.schema.json)
  2. [FrontendRuntimeType] attribute on property (overrides ambiguous types)
  3. [FrontendNoTransform] attribute on property (skips transformation)
  4. Runtime options: { dateBackend: momentDateBackend }

C# DTO
    |
    v
Typewriter Engine (v4.8.0)
    |-- TypeScript types (via DateLibraryProfiles + TypeScriptTypeMapper)
    |-- Runtime schemas (via .tst templates -> *.schema.ts)
    |-- Type registry (via .tst templates -> typewriter-registry.ts)
    |
    v
Runtime Transformer (typewriter-runtime)
    |-- transformJson(json, schema, registry, { dateBackend })
    |-- serializeJson(value, schema, registry, { dateBackend })
    |
    v
HTTP Adapters
    |-- Angular: withTypewriterResponseSchema() / withTypewriterRequestSchema()
    |-- Axios: responseSchema / requestSchema in AxiosRequestConfig
    |-- Fetch: fetchJson(url, schema, init, { registry })
    |-- TanStack Query: fetchJson() inside queryFn
    |-- RTK Query: createSchemaTransformResponse() in transformResponse
    |
    v
Correctly hydrated TypeScript objects
```
